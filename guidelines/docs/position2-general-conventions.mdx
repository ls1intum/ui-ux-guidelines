# General Conventions

## 🏠 Landing Page
- **Features & FAQs** should be prominently displayed to help new users understand what the app is used for.
- The **Login button** should be highly visible for quick access.
- **Most features** should be accessible **before requiring login** (avoid an early login wall).

## Header Design
- Should include (in this order):
  - **App Name** + **Version Number**
  - **Dark Mode Toggle 🌙/☀️** (follow the system setting until the user picks a mode, and remember the choice)
  - **Login Button**
- Should be max. **3.75rem in height**.
- Should make use of the **primary color theme**.

## Footer Design
- Should include:
  - **"Built by"** attribution 👨‍💻
  - **About & Legal pages** 📜 (imprint, privacy policy, and an [accessibility statement](/docs/accessibility#legal-context) with a way to report barriers)
  - **Commit SHA and version** of deployed app
  - **Bug report / feature request link** 🐞
- **Non-sticky**: The footer should **not** remain fixed while scrolling.

## 📂 Project/Course Page
- **Projects/Courses should be displayed as cards** instead of a list for better **visual clarity**.
  The cards should include the **title of the project/course** as well as **most relevant information about the project/course**
- **No sidebar** should be used on the **main project/course page**.

## ⏩ Sidebar Navigation
- **Project context** should be displayed at the **top** of the sidebar, which can be used to quickly switch projects.
- The other items should only be **used for switching different in-project contexts** but **not for switching between projects**.
- **Project settings** should be placed **at the bottom** of the sidebar with a divider above.
- Items in the sidebar should contain an **icon** and a **short text**.
- Sidebar should be **collapsible & expandable** via a **prominent chevron icon**.
- Should make use of the **primary color theme** or be at least visually highlighted.
- On mobile devices:
  - there should be a **sidebar icon or burger menu icon** on the far left of the header to expand the sidebar.
  - the sidebar should be hidden by default.

## 🔐 Authentication
- If **Keycloak** is used, apply a **shared AET login theme** instead of the Keycloak default, so that all AET apps offer the same login experience.
  [Keycloakify](https://www.keycloakify.dev/) lets you build such a theme with React, Angular, or Svelte (Helios does this, see the example below).
  [keycloak-tum-login-theme](https://github.com/ls1intum/keycloak-tum-login-theme) contains a TUM-styled Keycloak theme with passkey support.
- Make the login **accessible** ([WCAG 2.2, 3.3.8](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html)):
  - Allow **password managers** and **pasting** into all login fields (correct `autocomplete` attributes, no paste blocking).
  - Prefer **single sign-on** and **passkeys** over passwords.
  - Don’t use puzzle CAPTCHAs or ask users to transcribe codes without an alternative.

  - 📸 **Features with screenshots** for clarity.
  - 🤝 **Contributor information** to acknowledge contributions.
  - 🛠️ **Developer details** such as **version number, GitHub SHA** etc.

## Color Theme
Use the **[TUM AET UI component library](/docs/component-library)**. It ships the AET color theme as design tokens (`--tumaet-ui-primary-color` and others) with a matching dark theme, for Angular (`@tumaet/ui-angular`) and React (`@tumaet/ui-react`).

It uses a similar color theme as the main TUM website.
Please use - if possible - only the provided colors on the page, through the tokens and not as hard-coded values.

### Legacy: PrimeNG
Applications that still use PrimeNG can use the [sample theme config file for PrimeNG](./assets/general-conventions/primeng.config.ts) until they migrate.
It amends the [Aura preset](https://github.com/primefaces/primeuix/tree/main/packages/themes/src/presets/aura) and uses the same primary color.
The presets are published as `@primeuix/themes`; the older `@primeng/themes` package is deprecated.

Thanks for following these recommendations, with that we ensure a **modern, accessible, and user-friendly** experience for AET web applications! 🚀
